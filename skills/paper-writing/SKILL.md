# 论文写作

交付主线是 **Markdown**（`projects\<课题>\drafts\*.md`），用户要 Word/LaTeX 时再转。所有引用写成 `[@refkey]`，键来自 `<库根>\refs\refs.json`。

## 0. 动笔前的证据纪律（先读，再写）

1. 稿子里的每个数字、每张图，都要能指回库里的东西：
   - 图 → `projects\<课题>\figures\<figN>.json` 溯源侧车
   - 表/统计量 → `projects\<课题>\tables\` 或 `register-figure --params` 里记的参数
   - 引用 → `refs.json` 里的 `key`
2. 查不到出处的数字 **不许写进稿子**。要写就写"待补"，并在汇报里明确列出来。**编数据、编引用、编实验结果，是这个模式里最严重的错误。**
3. 用户给的中文稿是唯一的事实来源。**翻译与润色不得改变事实、数字、单位、逻辑关系、结论强度**（"可能"不能翻成 "demonstrates"，"显著"要有检验支撑）。
4. 需要文献支撑时先加载 `literature-refs`；需要期刊格式时先加载 `journal-profile`。

## 1. 开工前先看现状

```powershell
& '<库根>\.research\bin\py.cmd' '<库根>\.research\scripts\research.py' list-figures --project <课题>
```

先确认：有几个图、图号是什么、有没有 `caption`。**不要用稿子里提到的图号去猜侧车**，以 `list-figures` 为准。

## 2. 图注（Figure Caption）

标准结构（一句到底，Title Case 或句首大写按期刊档案）：

```
Figure N. <一句话说清这张图是什么> <关键条件/方法> <panel 说明> <统计与误差说明>.
(a) ...; (b) .... Error bars represent s.d. (n = 3).
```

要点：
- 图注必须能**独立读懂**：不依赖正文也能知道画的是什么、什么条件、什么单位。
- 每个 panel 的 `(a)` `(b)` 与图内标注逐一对应，顺序一致。
- 误差棒必须说明来源：`s.d.` / `s.e.m.` / `95% CI` / `n = ?`。**图里没有误差棒就不要在图注里提误差棒。**
- 统计显著性：写清检验方法与阈值（`two-tailed Student's t-test, *P < 0.05`）。
- 单位与符号按期刊档案；温度、浓度、时间不要混用中英。
- 有模拟数据时必须写明 `simulated`。
- 中文图注与英文图注**分开写**，不要中英夹杂。稿子里图注的位置与编号要和 `register-figure` 的 `caption` 一致，改图后回稿要同步改。

## 3. Results

逐段 = **一个论断 + 支撑证据 + 具体数字**。顺序对应图的顺序。

- 段落开头给结论性主句，后面才是数据（不要从"我们测量了…"这种流水账开头）。
- 数字带不确定度与样本量；比较句给方向和幅度（"提高了 23%（从 1.2 到 1.5 mAh g⁻¹）"）。
- 只描述观察，不解释机制（机制留给 Discussion）。
- 不重复图注里已有的方法细节；不给未展示的数据下结论。
- 时态：自己的结果用过去时，普遍成立的规律用现在时。

## 4. Discussion / 讨论结构与框架

推荐骨架（按需裁剪，不硬套）：

1. **重述核心发现**（一到两句，不复述 Results 细节）
2. **与已有工作比较**：谁做了什么、我们一致在哪、不一致在哪 —— 每处比较都要有 `[@key]`
3. **机理解释**：我们能支持到什么程度，哪些是推测（明确写 "we speculate / 可能"）
4. **局限**：样本、方法、外推边界，如实写
5. **意义与展望**：能落到什么结论，下一步做什么

"讨论论文结构和框架"这类请求：先给**大纲**（章节 + 每节一句话主旨 + 关键证据位 + 需要的文献），等用户确认大纲再写正文。不要直接吐一整篇。

## 5. 中→英与润色

- 中→英：先忠实直译出**完整信息**，再按英文习惯重组句子，最后逐句核对数字/单位/逻辑无遗漏。长句拆短，一个句子一个主张。
- 润色：给"改前 / 改后 / 为什么改"，让用户能判断，而不是静默替换。保留用户自己的语气，不要全部改成同一种句式。
- 中式英语高频问题（逐条自查）：主谓一致、冠词（a/the/零冠词）、可数不可数、时态一致、平行结构、`respectively` 的位置、`significant` 的滥用（无统计检验不要用）、`obvious/novel/very` 这类空词、`In this paper, we...` 的堆砌。
- 术语一致性：同一概念全文只用一个词（先列术语表，再逐段核对）。缩写首次出现给全称。
- 数字与单位格式统一（`1.2 × 10⁻³` 而非混排；`°C` 不留空格；单位与数值间空格按期刊）。

## 6. 回复审稿意见（Response Letter）

产物：`notes\response-<日期>.md`，逐条回复，格式：

```
### Reviewer 1, Comment 3
> <审稿人原文逐字引用>

**Response:** <答复：做了什么 / 为什么这样做>
**Change:** <稿子里改了什么，引用修改后原文，给出位置（Section 3.2, p.7, lines 120-126）>
```

纪律：
- **逐条编号回复，一条不漏**，包括批评性的和不认同的。
- 不认同就讲理由 + 给证据（补数据、补文献），**不空口道歉，也不硬顶**；语气专业、感谢具体。
- 每一条 "Change" 必须真的落到稿子里，或明确说"未改动，理由如下"。
- 补做的实验/分析若来自模拟或有限样本，必须写明。
- 颜色标记修改处（`\textcolor{blue}{}` / Word 高亮）的做法在 Markdown 里用 `**改**` 或 HTML 注释标出，转 Word 时再套格式。

## 7. 交稿前自检（缺一不可）

- [ ] `check-citations --draft <路径>` 退出码 0（非 0 就修，不许绕过）
- [ ] 每个数字能指回图/表；没有孤立的、无出处的数字
- [ ] 图号、图注、正文引用三者一致
- [ ] 术语表与缩写一致；单位格式统一
- [ ] 图表在稿子里的编号与 `list-figures` 一致
- [ ] 汇报时列出"仍待补 / 存疑"的清单，不含糊过去
