# 图内选区与模型对话（figure-chat）决策记录

> 拷打强度：细问。用户原话：「科研库能有一个与模型对话的端口……不是现在这样的对话式，我希望能有一个可以随时在某一个图里选区标注然后跟 ai 模型交流的功能」。
> 本文件只记**结论 + 理由**，每定一条追加一条；未定的进「待定」。

## 已确定

### D5 改动只做两类：图上加标注、数据变换
「改图版式参数（线宽/配色/字号/坐标轴）」不做 —— 图是 Origin 画的，面板给不出可靠的重画结果，只按用户的判断留一句话：宁可没有，也不做粗糙的。
理由：用户多选时只勾了「图上加标注」和「数据变换」，明确排除了版式参数。

### D6 副本：同目录 + 时间戳，覆盖前原件留 `.bak`
副本写成 `<基名>.trial-YYYYMMDD-HHmm.<ext>`，与原件同目录；确认覆盖时把原件改名成 `.bak` 再写正式名。
理由：用户选「同目录 + 时间戳」，并要「再次确认无误后决定是否覆盖」。

### D7 模型只出计划，执行永远是用户按的
模型只能返回一份改动计划（改哪个文件、改成什么、影响什么）；执行按钮由用户按，且必须走既有的 plan → confirm。
理由：用户选「只出计划」。

### D8 对话按图存档
每张图一条对话线，存 `.research/chats/<图号>.json`；重开面板能接上。
理由：用户选「每图一条」。

### D9 标注存矢量层，导出时才烘焙
标注存成 `annot.json`（可再次编辑），面板看的时候叠在图上；要投稿时再烘焙出 PNG 副本。
理由：用户选「矢量标注层 + 需要时烘焙」。

### D10 数据变换只出副本 + 对比
变换写 `data/<名>.trial-<时间戳>.<ext>`，给统计对比（点数/均值/基线前后差），不动原图、不改侧车指针。
理由：用户选「只出副本 + 对比」。

### D11 入口是全局快捷键，不占页签
按一下快捷键就能在图里出选区，快捷键要注意不与宿主已有组合冲突。
理由：用户否掉了「行内按钮 / 单独页签 / 放草稿里」，要全局快捷键。

### D1 产出物：问答 + 手动存笔记 + 可触发写动作（要双确认 + 副本）
圈选提问后，模型回答显示在面板里；用户可一键存进该课题的笔记；如果模型判断需要改东西，只能生成**清晰的改动计划**，用户确认后**改在副本上**，肉眼核对无误再决定是否覆盖原件。
理由：用户明确要「清楚计划 → 确认 → 副本上改 → 再确认 → 覆盖」。任何一步都不能跳过，模型不直接写原件。

### D2 喂给模型的上下文：选区裁切 + 整图 + 该图侧车
一次提问带三样：用户圈出的那块（裁切图）、整张图（看整体结构）、该图侧车文件（源数据、图版式参数、目标期刊）。
理由：只给选区模型不知道上下文；只给整图又看不清细节。侧车是复现信息，模型判断「这峰是不是杂相」时需要知道来源与处理。

### D3 决策记录落在本文件
理由：用户选了「要，写成文件」，这条功能的设计还会反复，需要一处可追溯的结论。

### D4 模型来源：宿主已配置的模型
用 DSH 的模型服务（`ctx.get('llm')`：`listProviders` / `listModels` / `stream`），面板里选一个已配置的模型，不另填 API key，不把密钥带进面板。
理由：用户要求「模型可以从已填写的 api 模型里选择」；密钥留在宿主，面板不碰。

## 实现状态（2026-11-01）

已落地（`lib/client.js` 的 `FigureChat`）：

- `Alt+Q` 开关选区，图上拖动出矩形，松手即裁出选区（canvas，归一化坐标 → 原图像素）。
- 模型选择读宿主已配置的模型（`ctx.get('llm').listProviders() / listModels()`），选择记在 `localStorage`。
- 请求体 = 文字（图号 / 页签 / 源数据 / 目标期刊 / 图注 + 用户问题 + 「只描述真看到的、要改只给计划」）+ 选区 PNG + 整图。
- 回答用 `stream` 流式渲染（`text-delta` 累加）。
- 「存进笔记」把这段问答整理成一条笔记，走 `notes.save` 的「计划 → 确认」，不直连写盘。
- 对话按 `figures/<图号>` 存在浏览器本地（`research-panel-chat:<图号>`），重开面板能接上。

还没做（按 D1/D8/D9 记着，别当成已完成）：

- D8 的「存 `.research/chats/<图号>.json`」——现在是浏览器本地，**没有**进库；要在别的机器上看到得走「存进笔记」。
- D9 的矢量标注层：引擎与 CLI 已做（`research.py annot add|render`，落 `.research/annot/<图号>.json` + `<基名>.annot.svg`），**面板里没有按钮**（用户要求由 AI 调）；面板侧尚未接「把模型给的标注改成 annot 命令」这一环。
- D6 的副本覆盖流程（`.trial-<时间戳>`）。
- D10 的数据变换副本 + 对比。
- 选区只支持矩形，没有多选区、没有峰位吸附。

## 仍未定（留给下一轮）

- **图上的注记与找峰这两件事不设面板按钮**（用户 2026-11-01 明确）：都由主会话的 AI 来做——注记按 `annot.json` 生成、找峰跑 `research.py analyze`。面板只负责把结果和图摆出来，不再往工具栏里加自动化按键。
- **失败与费用**：模型不可用 / 超时 / 单次 token 上限怎么降级；是否显示耗时与用量。
- **选区交互细节**：要不要峰位吸附、多选区、自由笔刷。
- **标注层的编辑方式**：`annot.json` 的字段还没定（箭头 / 文字 / 圈 / 峰位标记各自要存什么）；烘焙导出的脚本也还没有。
- **副本覆盖的具体交互**：`.trial-<时间戳>` 生成后，面板里怎么并排比对、覆盖前要不要强制留 `.bak`。
